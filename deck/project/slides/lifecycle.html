Where RL fits in a model's life

1 · Pretraining

Predict the next token on web-scale text.

Adds knowledge.

Acme: base

2 · SFT / LoRA

Imitate prompt → reply examples.

Adds instruction following: format, style, domain.

Acme: lora

3 · RL (RLHF, DPO)

Optimise a reward, usually from human preferences.

Adds judgement: which plausible reply is better.

Acme: rl

Modern base models already answer questions (the web is full of Q&A), but generically: not Acme's facts, format or refusals.

The lifecycle recap. Pretraining gives knowledge. Supervised fine-tuning, cheaply via LoRA, gives instruction following for a specific job. RL gives judgement. In the notebook, the base model does answer, since modern pretraining data contains plenty of Q&A, but generically. It invented a $10 free-shipping threshold and ignored the 3-bullet request. LoRA answers in Acme's voice. Vendor chat models behind APIs went through all three stages.
